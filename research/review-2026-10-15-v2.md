# Review of Qwen's September audit and v2 implementation

> Historical first-delivery findings. Several are now resolved; see
> [the current recheck](review-2026-10-15-v2-recheck.md) for verified fixes and remaining issues.

Verdict: **not ready to adopt/publish as delivered**. Calculation consistency passes,
but the public explanation, preservation requirements and chart labeling are incomplete.
Reviewed the current diff, audit, new assumptions, records, generator and research log
against the agreed user prompt and copy guide. No model assumptions or source code
changed in this review; no commit or deployment.

## Material findings

### 1. Public model page mixes v1 explanations with v2 tables; audit destination missing

`research/MODEL.md` still says Sep 9 baseline, Sep 19 assumptions, standoff 100.5M b/d,
old demand offsets and end-Feb cumulative endpoint −1832.6M. Its generated table now
uses the Oct 6 baseline, 101.30M b/d, no demand offset, endpoint −1608.6M. All three
v1 table blocks were replaced, so the original v1 tables were not preserved on the
model page. The original v1 chart and score table were not added there either.
The dashboard and navigation link to `/model#the-september-2026-audit`, but neither
the source heading nor the built HTML contains that destination. The audit lives
only in research. Restore a clearly labeled v1 presentation and add a separate v2
explanation/table and public audit. Numerical v1 records themselves ARE preserved.

### 2. Ghost datasets broke tooltip identities

In `site/src/pages/index.astro`, ghost datasets are inserted at indices 4–6; EIA,
recent trend and observed move to 7–9. Tooltip callbacks still treat 4/5/6 as EIA /
trend / observed and return null for 7–9. Thus v1 lines are mislabeled, and real
EIA/trend/observed lines lose tooltip labels. The EIA December 2026 direct label
still targets dataset 4 (v1 holds); the other endpoint labels correctly add the
three-dataset offset. Main v2 scenario tooltips still claim Sep 9 baseline.
Use consistent dataset identities/offsets throughout and exercise every toggle.

### 3. Audit overstates what September establishes

The EIA workbook values are valid and comparable with the v1 EIA baseline. A fresh
primary workbook download matches the archived Oct 6 workbook byte for byte.
But the audit still asserts that EIA P−C “reflects mostly the on-land drawdown” and
that oil-on-water explains the agency difference. No reconciliation establishes that.
The dashboard again asserts a combined cause rather than separating established
arithmetic from unresolved coverage differences.

The standoff decomposition is particularly important:

- v1 September P−C: −96.3109M.
- Updated EIA September P−C: −88.1288M.
- Difference within the EIA framework: **8.1821M**.
- EIA P−C versus IEA monthly −10M: **78.1288M**, an unresolved cross-measure gap.
- IEA monthly −10M versus frozen-anchor display −2M: **8M**, prior-period revision effect.
- Sum: **94.3109M**, reproducing the displayed standoff miss.

Standoff production is 0.8038M b/d below EIA's update, contributing 24.1138M more
withdrawals; consumption is 0.5311M b/d below EIA, offsetting 15.9317M of that.
Production is the larger component, but the conditional balance was only 8.2M away
from EIA's update. Do not attribute the full displayed miss to flat production.

September baseline consumption remaining near forecast does not, by itself, validate
removing all scenario-specific consumption adjustments through 2027. Setting holds
exactly equal to EIA's forecast and keeping standoff production flat for another
14 months are forward judgments, not results demonstrated by this audit. Document
why each conditional future assumption follows from the evidence, or leave it proposed.
The standoff definition also still says the Saudi bypass is closed with no restart
date, contradicting the verified restart and current scenario description.

The audit calls lapse “not scored against September,” but its September outcomes and
232M displayed error remain. Conditional applicability is a valid caveat; it cannot
silently change the frozen scoring policy. The gate section says changes are supported
for all three scenarios while the implementation intentionally retains lapse offsets.

### 4. Scorecard does not retain both versions or provide the required result

`wsScoreScenarioVersionRaw` selects only the newest version with outcomes. Once v2
has a score, v1 disappears instead of appearing alongside it for the same month.
Implement per-version rows/history and compare the same months. The required sentence
“The scenarios were less accurate than the recent-trend baseline in the first scored
month.” is absent. The note also no longer explicitly states the reported −10M
monthly change. Its claim that November is v2's first scored month is wrong: October
is scored too, but November is its first full future month.

### 5. Supposedly unchanged non-Gulf growth has shifted by one month

v1 adds 1/6M b/d in January 2027 through 2M in December. v2 starts additions at
zero in January and ends at about 1.83M in December, while saying the pace is held
unchanged. This introduces another assumption change. Preserve the intended schedule
or explicitly justify and version the timing change; do not silently repair inputs
in a copy review.

### 6. Required odds entry and test coverage remain incomplete

Calibration/odds values are unchanged, but no dated v2 production-revision entry was
added to `research/judgment-history.md`. Add the requested rationale without changing
probabilities. The assumptions file's issued_at is 22:30Z, whereas all three issued
records say 01:55:37Z the next UTC day; distinguish drafting from issuance instead of
calling both the finalization time.

`regen-scenarios.py --selftest` currently aborts during its second-version fixture:
`ambiguous current version: [...snapshot.json, ...snapshot2.json]`. The fixed synthetic
version 2026-10-15 collides with the newly issued real version. This is distinct from
the later pre-existing test failure mentioned in Qwen's log. The actual current
all-version drift check passes; that does not replace a passing issuance selftest.
