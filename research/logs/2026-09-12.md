- Three gotchas found the hard way (story kept internal per user — the public README
  carries only public facts; wrangler.jsonc keeps inline config comments; full story
  also in the project notes):
  1. Custom-domain routes take **bare hostnames** — `www.depletion.org/*` is rejected
     ("wildcard operators not allowed in Custom Domains").
  2. Defining `routes` **silently disables the workers.dev subdomain** in wrangler 4 —
     re-enabled explicitly with `"workers_dev": true` so old shared links keep working.
  3. Static assets default to **`serve_directly: true`** — assets are served at the edge
     and the worker never runs (apex 200, redirect dead). Fix: `"run_worker_first": true`,
     and in this wrangler (4.130) the assets binding must also be named explicitly:
     `"binding": "ASSETS"` (without it `env.ASSETS` is undefined → 500 on every page).
  Diagnostic that cracked #3: CF API `GET /accounts/{acc}/workers/scripts/oil-report/
  versions/{id}` shows `script_runtime.assets.serve_directly`; `wrangler dev` reproduces
  the 500 locally, but note dev builds URLs from the local origin so Host-header
  overrides don't change `url.hostname` — redirect logic must be tested on the real
  deploy.
