## Chart.js tooltip gotcha (fixed same day)

On a **linear x-scale**, Chart.js's default tooltip **title** prints the raw x value
(day-of-year, e.g. "250") — the `ticks.callback` is *not* consulted for tooltip titles. The
Brent and diesel charts were the only two date-axis charts missing a custom `title` callback,
so they showed raw day numbers on hover. Added title callbacks (date resolved from the series'
own array via dataIndex). Verified in a headless-Chrome harness: title now "Sep 9".

Also: `interaction: { mode: "index" }` pairs points by **array position, not date** — with
mismatched point counts (Brent 13 vs WTI 43; gasoline 36 vs diesel 11) the crosshair/tooltip
snap to the wrong place. Brent + crack charts now use `mode: "nearest", axis: "x"`.

## 16:45 — Refining section shipped, then broke every chart (fixed 16:47)

**Bug:** after deploying the Refining section (f29be160), ALL charts below the flip chart died.
`Uncaught ReferenceError: refineryMonths is not defined` killed module evaluation mid-script.

**Root cause — TWO import blocks in index.astro:**
1. Line 5 (frontmatter): for the *template* (`globalRefining.map`, `billLedger.map`, …)
2. Line ~898 (inside the big `<script>`): for the *chart code* (`brentYtd`, `worldBalance`, …)

The refinery names (`refineryMonths`, `usRefineryRuns2026`, `usRefineryRuns2025`) were added to
#1 only. The script block has its own scope — the compiler hoists the script's imports, left the
three names as free identifiers, and the bundle referenced globals that don't exist.

**Why nothing caught it:**
- Astro builds do NOT type-check (no `astro check` in the build) — missing imports are silent.
- The build "succeeds"; esbuild leaves unresolvable free identifiers as-is.
- The deployed bundle is minified — the raw `refineryMonths` identifier in a minified file is the tell.

**Verification method that works for this page** (module scripts with `/_astro/` abs paths):
1. `curl` the live page + both `/_astro` assets into a local dir, serve with `python3 -m http.server`
2. headless Chrome `--dump-dom http://127.0.0.1:8765/` and read **stderr** — Chrome logs
   `CONSOLE` errors there. Zero errors ⇒ every `new Chart()` got its canvas (Chart.js throws on failure).
3. file:// copies of the page NEVER work (ES modules over file:// are CORS-blocked) — all canvases
   go blank, which mimics a real outage. Don't misread that.
4. In standalone harnesses, set `animation: false` or `--virtual-time-budget` leaves points frozen at
   their animation-start position (y-axis looks collapsed) — harness artifact, not a bug.

**Rule going forward:** any name used in the chart `<script>` must be in the SCRIPT's import
(inside the `<script>` block), not the frontmatter import. After any data change: grep the built
bundle for a distinctive new value (e.g. `16.33`) before calling it deployed.

Deployed: 4c9b9764 (fixed). Version f29be160 was the broken one.
