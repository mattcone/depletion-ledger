### P2 — Date exceptions hide unrelated future date changes

**Claim:** exceptions suppress flags only while the API retains its known placeholder date; any other change re-flags.

**Observed:** line 291 compares the local date only to RECONCILED_DATES, never the incoming date to the known placeholder. Once the local date is the exception, every incoming date is suppressed.

**Reproduction:** changed #166's API date to October 20 in an isolated mock; the script reports “Up to date — nothing to do” rather than flagging the new date. Temporary artifacts: `/tmp/ukmto-date-check-4da1n8by`. This fabricated test date demonstrates the branch behavior; it is not a source correction.

**Requested correction:** limit suppression to the specifically reviewed local-date/API-placeholder pair (and appropriate identity), and test both that pair and a different incoming date.

**Additional interface issue:** the script advertises no writes for its default mode, but updates the identity sidecar outside the --apply gate. The mock used here happened to serialize identical bytes; the code still calls saveIdentities, and different lastSeen dates or aliases will change the file. Either make read-only/dry-run modes read-only or explicitly document the metadata-write behavior.
