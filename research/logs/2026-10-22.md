## ~15:30 MDT — ingestion bug fixes (recheck follow-through)

The recheck of my Oct 22 ingestion fixes found two real bugs (full
reproductions in the review handoff). Both fixed, with a permanent regression
test:

**Bug 1 — duplicate protection self-poisoned on the second run.** The sidecar
update ran on every fetch and overwrote the record's incidentNumber with the
flagged alias: run 1 flagged #200 and recorded it, run 2 saw the sidecar
already saying #200 and appended it as legitimate. Fixed by splitting the
sidecar record into `canonical` (the number the array counts) and `aliases`
(observations under other numbers). Observing an alias never overwrites the
canonical; the canonical follows whatever the array counts, so a manual
reconcile to a new slot is picked up on the next run (T4). The sidecar file
was migrated to the new shape (`incidentNumber` → `canonical`).

**Bug 2 — date exceptions were too broad.** The suppression compared the local
date to the exception value only, so once the local date was the exception,
ANY incoming date was silently ignored (the repro: #166 API date moved to
Oct 20 → "Up to date" instead of a flag). Suppression is now scoped to the
exact reviewed pair — local date === report-body date AND API date === the
known placeholder, type unchanged — for each of #166 (10-11/10-12), #172 and
#173 (10-13/10-14). Any other combination re-flags.

**Interface fix.** The default mode advertised "no writes" but still updated
the sidecar. The sidecar is now written ONLY on --apply (quiet-day apply and
post-merge apply, against the post-merge array); read-only and dry-run modes
make zero writes — verified byte-identical on a real fetch.

**Regression test: `site/scripts/ukmto-fetch.test.mjs`** (no framework;
`node scripts/ukmto-fetch.test.mjs`, exits 1 on failure). 24 assertions, all
passing: the repeated-apply re-slot repro (flagged on both runs, never
appended, alias not double-recorded), read-only-then-apply, missing-sidecar
read-only, the exact date pair (suppressed) vs an unrelated date change and a
